# v0.16.0 — US/Canada bank connections

Adds a Plaid Transactions connector under **Imports → Connect US and Canadian banks**:
provider configuration, hosted bank sign-in, account mapping, cursor-based sync,
posted-transaction preview, duplicate protection, reconnection and remote disconnect.

Bank secrets and access tokens are encrypted using the existing persisted data-
protection keyring. Settings and connection responses do not return those secrets.
Downloaded data stays in a separate review queue until selected in import review.
Pending entries do not post; modified/removed bank records never silently rewrite
already imported history. Bank balances are informational and do not change opening
balances. USD/CAD deposit/card accounts are supported; other same-currency ISO account
feeds may be available from the provider, but investments and loans are excluded.

**Real banks require your own Plaid Production access and credentials. Sandbox is
for test banks only.** This integration does not require OpenAI. Sync is manual and
retrieves available provider data; background jobs, webhooks and forced bank refresh
are not included. Live production bank login has not been validated here.

The schema update is additive. JSON backup remains version 6; portable backups
exclude bank credentials/connections/queues and clear existing mappings on restore.
Preserve PostgreSQL and the keyring volume for normal updates and full-server backups.

See [bank setup and accounting behavior](../bank-connections.md) for browser setup,
OAuth/Synology details, limits and reconnect/restore behavior.

## Validation

188 backend tests (8 domain, 180 API), 136 frontend tests, the production frontend
build and seven PostgreSQL/Chromium workflows pass. Provider tests cover fixed
hosts, sanitized errors, encryption, ownership, mappings, cursor pagination and
rollback, initial-data-not-ready, duplicate imports, changed/removed transactions,
reconnection and disconnect. The bank browser scenario simulates Plaid Link and
provider responses but commits through the real API/PostgreSQL. A separate synthetic
PostgreSQL check verified bank-table foreign keys, mapping reset on JSON restore
and user-data reset without any provider network calls. Existing transaction counts
were unchanged by schema initialization. Graph refresh was attempted, but graphify
is unavailable in this environment.
